## 그래프의 개념
| 구성 요소 | 설명 |
|---|---|
| 정점(vertex/node) | 그래프의 한 점, 데이터 저장 등에 사용 |
| 간선(edge) | 노드와 노드를 연결하는 선 |
| 가중치 | 간선에 할당된 값 또는 비용 |
| 방향성 | 방향 그래프는 간선 방향으로만 이동, 무방향 그래프는 양방향 이동 가능 |

### 구현 방법
| 방법 | 구조 | 특징 |
|---|---|---|
| 인접 리스트 | 각 노드마다 인접 노드를 연결 리스트로 표현, N개 리스트 사용 | 간선이 적을 때 공간 효율적 |
| 인접 행렬 | 2차원 배열, N개 노드면 N×N | 간선 존재 확인이 빠르지만 공간을 많이 씀 |

- 두 방법의 장단점을 확인한 뒤 적용해야 함

## 그래프 탐색
| 알고리즘 | 방식 | 구현 |
|---|---|---|
| 너비 우선 탐색(BFS) | 루트에서 인접한 노드를 먼저 방문하고 넓게 탐색 | 큐 |
| 깊이 우선 탐색(DFS) | 루트에서 가장 깊은 정점까지 내려간 뒤 되돌아옴 | 스택 또는 재귀 호출 |

- BFS 예: 6개 노드·6개 간선 그래프에서 시작 1을 큐에 넣고, 꺼낼 때마다 인접 노드를 넣음
  - 1 추출 → 2, 3, 4 삽입 → 2 추출(5 삽입) → 3 추출(5는 이미 있음) → 4 추출(6 삽입) → 5 추출(새 이웃 없음) → 6 추출 → 큐가 비면 종료
  - 방문 순서: 1, 2, 3, 4, 5, 6

## 최단 경로 알고리즘
| 문제 | 내용 | 대표 알고리즘 |
|---|---|---|
| 단일 출발점 | 한 출발점에서 모든 정점까지 | 다익스트라, Bellman-Ford |
| 단일 쌍 | 특정 두 정점 사이 | 다익스트라, A* 탐색 |
| 단일 도착점 | 모든 정점에서 특정 정점까지 | 다익스트라 |
| 모든 쌍 | 모든 정점 쌍 사이 | 플로이드, 존슨 |

## 트리
- 비선형 자료 구조로, 계층적 관계를 표현할 수 있는 사이클이 없는 연결 그래프

| 용어 | 설명 |
|---|---|
| 루트 | 계층 맨 위, 부모가 없는 노드 |
| 레벨 | 루트를 0으로 출발해 자신에 도달하는 거리 |
| 높이(깊이) | 트리의 가장 높은 레벨 |
| 가지 | 부모와 자식 간의 경로(간선) |
| 조상 | 자신에게 오는 경로의 모든 노드 |
| 부모 / 자식 | 레벨 N과 N-1 / N+1로 연결된 노드 |
| 형제 | 같은 부모를 갖는 노드 |
| 차수 | 자식 수, 하위 트리 개수 |
| 트리의 차수 | 모든 노드 차수 중 최대값 |
| 단말(리프) | 자식이 없는 노드, 차수 0 |
| 서브트리 | 자식 노드를 루트로 하는 트리, 개수는 차수와 같음 |
| 숲 | 여러 개의 트리 |

## B-Tree
- 최소 2개의 자식 노드와 적어도 한 개의 값을 가지며, 최소 1/2 이상 채워진 상태로 데이터를 정렬해 탐색·삽입·삭제·순차 접근이 가능하도록 유지하는 트리
- B는 Balanced의 의미로, 리프 노드가 한쪽으로 쏠리는(skewed) 현상이 적음
- 자식 노드가 2개 이상인 트리, 트리 높이를 완전히 동등하게 유지

### 특징
| 특징 | 설명 |
|---|---|
| 트리 높이 동일 | 탐색 속도를 균등하게 보장 |
| Non binary tree | 한 노드에 여러 데이터 값을 저장 |
| 최대값 정의 | Max Degree - 1개의 데이터 |
| 정렬 구조 | 한 노드 안의 키 값은 오름차순 유지 |

### 주요 규칙
1. 자식 노드 수 = 부모 노드의 데이터 수 + 1
2. 모든 노드의 데이터는 순서대로 정렬, 한 노드 안 키는 오름차순
3. 루트와 리프를 제외한 내부 노드는 최소 ⌈m/2⌉, 최대 m개의 서브트리를 갖고, 적어도 ⌈m/2⌉-1개의 키를 가짐(차수가 홀수면 내림 적용)
4. 모든 리프는 같은 레벨에 있음(균형 트리)

### 장단점
| 장점 | 단점 |
|---|---|
| 삽입·삭제 후에도 균형 유지 | 삽입·삭제 시 균형을 위해 재분배·합병 등 복잡한 연산 필요 |
| 효율적인 알고리즘 | 순차 탐색 시 중위 순회로 비효율(B+ 트리에서 리프 간 연결 리스트로 개선) |
| 저장 장치의 효율성 | - |
| 균등한 탐색 속도 | - |

### 삽입 예 (Max degree 3, 입력: 2 6 5 11 8 10 12 7 3 1 9 4)
- 루트에 정렬해 넣다가 Max Degree에 도달하면 노드를 분화하고, 분화 시 리프는 같은 레벨 유지
- 분화시킬 노드가 루트가 아니면 분화 후 서브트리를 부모로 한 단계 올림(합병)
- 부모도 분화 대상이 되면 같은 과정을 반복
- 삭제로 최소 데이터·노드 수가 부족해지면 부모·형제 노드와 재배치

## B+ Tree
- 데이터가 순차적으로 처리되어야 할 때 트리 내부를 오르내리는 시간이 커지는 문제를 해결하려고 사용
- B-Tree와 차이
  - 모든 데이터 엔트리는 단말(리프) 노드에 둠
  - 내부 노드에도 같은 키가 있을 수 있지만 찾기 용도로만 쓰이고 데이터를 갖지 않음
  - 각 리프 노드는 다음 리프를 가리키는 추가 포인터를 가짐
- 구조
  - 인덱스 세트: 키와 포인터만 존재. 리프에 있는 키를 찾아갈 직접 경로 제공
  - 순차 세트: 데이터만 존재. 리프 값은 오름차순 정렬, 삽입으로 분기해도 연결이 유지되어 순차성 확보
- 삭제는 리프에서만 수행하고, 키 값은 인덱스 세트에 남아 split 값으로만 쓰임

## B* Tree
- B 트리가 삽입 시 분열이 잦아 성능이 떨어지는 점을 개선한 알고리즘
- 분열·합병보다 노드 간 값 재배치가 알고리즘적으로 단순하다는 점을 이용해, 형제 노드가 다 찰 때까지 분열을 늦춤 → 삽입 속도 향상, 평균 공간 사용률 증가
- 루트와 리프를 제외한 모든 노드가 최소 2/3를 키로 채우도록 제한하는 다중 검색 트리
- 특징
  - 리프를 제외한 모든 노드는 m개 이상의 서브트리를 가질 수 없음
  - 루트·리프를 제외한 모든 노드는 적어도 ⌈(2m-2)/3⌉+1개의 서브트리를 가짐
  - 루트는 리프가 아닌 이상 최소 2개, 최대 2⌈(2m-2)/3⌉+1개의 서브트리를 가짐
  - 모든 리프는 같은 레벨
  - 리프가 아닌 노드의 키 수는 서브트리 수보다 하나 적음
  - 각 리프는 최소 ⌈(2m-2)/3⌉, 최대 m-1개의 키를 가짐
- 재분배: 넘침이 생기면 즉시 분리하지 않고 새 노드 생성을 지연하며 형제 노드 간에 재분배. 모든 형제가 꽉 찼을 때만 분리하고, 분리하면 두 개의 꽉 찬 형제에서 데이터를 균등 분배해 세 노드를 모두 2/3로 채움

## 세 트리 비교
| 구분 | B-Tree | B+ Tree | B* Tree |
|---|---|---|---|
| 구조 특징 | 루트~리프 동일, 분열 시 보조 연산 | 인덱스 세트·순차 세트 구성, 전체 데이터는 순차 세트 | 넘침은 형제로 분열, 부족은 형제와 결합 |
| 순차 접근 | 중위 순회 | 리프 노드만 검색 | 중위 순회 |
| 직접 접근 | 트리 순회 | 인덱스 세트 순회 | 트리 순회 |
| 속도 | 보통(소량 검색 유리) | 순차 검색 빠름 | B 트리보다 빠름 |
| 중복성 | 탐색 키 중복 없음 | 인덱스·순차 세트 중복 | 탐색 키 중복 없음 |
| 분열 기준 | 노드의 1/2 이상 찼을 때 | 노드의 1/2 이상 찼을 때 | 노드의 2/3 이상 찼을 때 |
| 노드 관리 | 리프 아닌 노드가 더 큼, 저장 공간 관리 복잡 | 노드 크기 동일, 삭제 노드는 리프에 존재 | 리프 아닌 노드가 더 큼 |

## 정리
- 그래프는 "관계"를 다루는 자료 구조이고, 탐색은 큐(BFS)·스택(DFS), 최단 경로는 출발/도착 조건에 따라 알고리즘을 고른다
- B 계열 트리는 디스크 같은 저장 장치에서 높이를 낮춰 탐색 횟수를 줄이는 것이 목적이며, B+는 순차 접근, B*는 공간 사용률을 개선한 변형이다
