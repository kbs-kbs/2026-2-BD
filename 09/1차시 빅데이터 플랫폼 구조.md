## 빅데이터 플랫폼의 개념
- 빅데이터 기술을 잘 사용할 수 있도록 준비된 환경으로, 빅데이터 기술의 집합체
- 구성 흐름: 수집·정제 → 저장·관리 → 처리 → 분석 → 표현
- 사용자 측면 요소: 사용자 인터페이스, 성능 관리, 비용 절감, 서비스 품질 관리, 인증·접속 관리, 자원 관리, 보안
- 제공자 측면 요소: 위 요소를 실제로 돌리는 문제 해결 환경

### 처리 부하의 종류
| 부하 | 발생 지점 | 부하 제어 예 |
|---|---|---|
| 컴퓨팅 부하 | CPU 등 자원 소비 | CPU 성능 향상, 클러스터의 효과적 자원 할당 |
| 저장 부하 | 입력·중간·출력 데이터 저장 | 파일 시스템 개선, 메모리·파일 시스템의 효과적 사용, DB 기술 향상 |
| 네트워크 부하 | 노드 간 통신 | 노드 간 대역폭 효과적 분배, 네트워크상 가까운 노드 선택 |

## 요소 기술
### 수집 및 정제(Cleaning)
- 데이터 정제는 품질을 높이려고 데이터의 오류·불일치를 감지·제거하는 것
- ETL 프로세스
  - 추출(Extraction): 데이터 소스에서 데이터 추출
  - 변환(Transformation): 추출한 데이터를 변환·균질화·정제하고, 데이터 웨어하우스 스키마에 맞게 변환. 비즈니스 규칙·통합 제약에 따라 필터링·확인
  - 로딩(Loading): 변환된 데이터를 데이터 웨어하우스로 적재

### 저장 및 관리
- NoSQL은 RDBMS의 ACID(원자성·일관성·독립성·지속성)를 포기하는 대신 즉각적인 갱신이 가능한 저장소
- CAP 이론 관점에서 네트워크 분할 감내성을 취하고 일관성·가용성 중 하나를 포기하므로, 둘을 함께 취하는 RDBMS보다 성능·확장성이 높음
- 확장성을 얻으려면 작은 범위의 동작·트랜잭션을 사용해야 함
- 분산 파일 시스템으로 나눠 저장하면 신속한 공급이 가능해 처리 성능이 향상

### 처리
| 구분 | 정의 |
|---|---|
| 병렬 시스템 | CPU 등 자원을 데이터 버스·지역 통신 시스템으로 연결해 분할된 작업을 동시에 처리, 계산 속도를 높임 |
| 분산 시스템 | 네트워크로 분산된 컴퓨터를 단일 시스템 형태로 구동. 각 노드는 독립된 시스템이어야 함 |

- 두 용어는 중첩되는 부분이 많아 실제 시스템에서 명확히 구분하기 어려우므로, 강의에서는 **분산 병렬 컴퓨팅**으로 아우름
- 네트워크와 미들웨어로 다수의 독립 자원을 하나의 시스템처럼 묶어 큰 문제를 처리

### 분산 병렬 컴퓨팅의 세 가지 문제
1. 전체 작업을 작은 작업으로 나누는 문제 — 워크플로우처럼 의존적인 작업은 스케줄링으로 순서를 정함
2. 프로세서 간 중간 결과를 주고받는 문제 — 효율적 통신이 성능과 직결. 단일 시스템은 노드 수만큼 균등 분할, 이종 시스템은 컴퓨팅 능력에 따라 분할. 그래프 분할 같은 기법으로 통신을 줄임
3. 동기화 문제 — 동기적 방법은 특정 계산이 끝나거나 데이터를 받을 때까지 기다리고, 비동기적 방법은 결과 메시지를 보낸 즉시 다음 작업을 계속하되 계산 과정의 적합성을 확인해야 함

### 맵리듀스
- 구글에서 개발한 대량 데이터 처리 프로그래밍 모델로 효과적 병렬·분산 처리 제공
- 맵은 입력을 처리해 중간 데이터를 만들고, 리듀스는 중간 데이터를 병합해 출력을 만듦
- 런타임의 입력 분할, 작업 스케줄링, 노드 고장 대응, 노드 간 데이터 전송이 성능에 큰 영향을 줌

처리 5단계
1. 입력 데이터를 읽고 분할
2. 분할된 입력을 할당해 맵 작업 수행, 중간 데이터를 통합·분할
3. 통합·분할된 중간 데이터를 셔플
4. 셔플된 중간 데이터로 리듀스 작업 수행
5. 출력 데이터를 생성하고 종료

- 세부 구조: 마스터 워커가 맵·리듀스 워커에 작업을 배분하고, 맵 워커는 중간 데이터 통합·분할, 리듀스 워커는 셔플된 데이터 정렬 후 리듀스 작업을 수행

### 분석
| 구분 | 내용 |
|---|---|
| 탐구 요인 분석(EFA) | 데이터 간 상호 관계를 파악해 분석 |
| 확인 요인 분석(CFA) | 관찰된 변수 집합 요소의 구조를 파악하는 통계적 기법으로 분석 |

- 목적·분야 특성에 맞는 분석 기법을 고르는 것이 중요

### 표현
- 처리·분석 결과를 표, 그래프 등으로 쉽게 이용하도록 표현해 결과를 더 효과적으로 분석하게 함

## 플랫폼 3계층 구조
| 계층 | 역할 | 주요 모듈 |
|---|---|---|
| 소프트웨어 계층 | 빅데이터 응용 구성, 처리·분석과 수집·정제 수행 | 데이터 처리·분석 엔진(처리/분석, 워크플로우, 표현), 데이터 수집·정제 모듈(추출·변환·로딩), 서비스·사용자 관리, 모니터링, 보안 |
| 플랫폼 계층 | 응용 실행을 위한 플랫폼, 데이터·자원 할당 | 사용자 요청 파싱, 작업 스케줄링, 데이터·자원 할당(초기 할당, 재할당·복제, 스케일링), 프로파일링(자원·응용·시뮬레이션), 데이터·자원 관리, 서비스·사용자 관리, 모니터링, 보안 |
| 인프라 계층 | 자원 배치·노드·스토리지·네트워크 관리 | 자원 배치(초기 배치, 재배치·스케일링), 노드 관리, 스토리지 관리, 네트워크 관리, 서비스·사용자 관리, 모니터링(서비스·자원), 보안 |

- 세 계층에 공통으로 붙는 모듈이 서비스 관리, 사용자 관리(인증·접속, 사용자 서비스, SLA), 모니터링, 보안이라는 점을 기억하면 구조가 단순해진다

## 정리
- 플랫폼은 결국 "수집·정제 → 저장 → 처리 → 분석 → 표현"의 파이프라인을 여러 사용자가 안정적으로 돌리게 하는 환경
- 부하를 컴퓨팅·저장·네트워크로 나눠 보면, 어느 계층의 모듈이 그 부하를 다루는지가 분명해진다
