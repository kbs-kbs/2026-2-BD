## 가상화 기술의 개요
- 실제로 존재하는 물리적 자원을 추상화해 논리적 자원 형태로 나타내는 기술
- 기존의 복잡한 물리 장치에서 컴퓨팅 자원을 분리시켜 효율적으로 활용·관리하게 해 줌

## 서버 가상화
- 물리 서버 하나에 여러 가상 서버를 구축해, 각 응용과 운영체제가 독립된 환경을 보장받게 함
- 동일한 물리 머신(PM)을 공유하는 가상 머신(VM)은 PM의 CPU·메모리·I/O를 분할해 사용하므로 서버 효율이 증가
- 데이터센터는 보통 약 10~15%의 활용도를 보이는데, 가상화된 서버는 70%가 넘는 활용도를 보임

### 호스트 기반 vs 베어메탈 기반
| 구분 | 구조 | 장점 | 단점 |
|---|---|---|---|
| 호스트 기반 | 하이퍼바이저가 호스트 운영체제 위에 설치 | 설치가 쉽고 구성이 편리 | 성능이 저하될 수 있음 |
| 베어메탈 기반 | 하이퍼바이저가 운영체제를 거치지 않고 하드웨어와 직접 연결 | 향상된 성능, 실시간 운영체제 지원 | 디바이스·하드웨어 플랫폼 드라이버를 포함해야 하고 설치·구성이 어려움 |

### 전가상화 vs 반가상화
| 구분 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 전가상화 | 하드웨어 전체를 가상화해 게스트 운영체제 실행 | 게스트 OS·응용 수정 불필요, 다른 물리 시스템으로 이송(Migration) 용이 | 지속적인 업데이트 등으로 성능 저하 |
| 반가상화 | 게스트 운영체제를 선택적으로 일부 수정해 성능을 높임 | 슬립 시간을 제한해 프로세서 자원을 효율적으로 분배 | 수정된 게스트 OS가 필요해 실제 하드웨어에서 직접 실행이 어려움 |

- 젠(Xen) 구조로 보면, 전가상화는 QEMU와 디바이스 드라이버를 통해 입출력을 에뮬레이션하고, 반가상화는 게스트에 PV 드라이버를 두어 프런트엔드-백엔드로 주고받음

## 데스크톱 가상화
- 데스크톱 환경을 잘게 쪼개 이기종의 가상 데스크톱 환경을 여러 개로 나누는 기술
- 중앙 서버 하나에서 데스크톱 자원을 나눠 각 사원에게 작업 환경을 제공하므로 개인·회사 작업 공간 분리가 가능
- 효과: 관리 시간·비용 감소, 데이터 외부 유출 방지, 통합 업그레이드·패치, 백업·복구 용이, 공간 절약·탄소 배출 감소
- 저장 방식에 따라 두 모드
  - 정적 모드: 데스크톱과 사용자가 1:1로 맵핑되어 각자 고유 데스크톱을 받고 이미지를 관리·유지
  - 동적 모드: 모든 사용자 데이터를 데스크톱에 나눠 저장. 로그인하면 VM 생성, 로그오프하면 데이터·설정 저장 후 VM 종료 → VM을 효과적으로 사용

## 스토리지 가상화
- 저장 장치의 실제 위치를 몰라도 여러 이기종 저장 장치를 저장 풀 하나로 만들어, 기기 간 데이터 이동·복제, 이기종 서버 간 블록 단위 공유를 제공
- 자원 활용률을 높여 시간·비용을 절약하고, 스토리지 크기 제약 없이 거의 무한한 확장성 제공
- 네 가지 형태
  - 디스크 컨트롤러 가상화: 컨트롤러가 여러 개 있는 것처럼 보이게 함
  - 스토리지 블록 가상화: 물리 스토리지에서 논리 스토리지를 추상화해 최종 사용자 스토리지를 유연하게 관리
  - 파일 가상화: 파일의 물리적 위치를 추상화, 중앙 파일 서버가 요청 시 실제 위치로 라우팅
  - 테이프 가상화: 디스크를 테이프 자원처럼 가상화해 백업이 테이프 드라이브에서 받는 것처럼 동작
- 분류 축: 호스트·서버 기반 / 네트워크 기반 / 스토리지 기기·서브시스템 기반, 그리고 인밴드·아웃오브밴드

## 네트워크 가상화
- 네트워크 인스턴스가 물리 네트워크 인프라를 공유하는 기술
- 라우터·스위치 등 네트워크 자원을 서로 공유해 여러 사용자를 하나의 가상 네트워크 환경으로 엮음
- VPN보다 확장된 개념으로, 트래픽 분리뿐 아니라 전체 관리·제어를 제공하고 서버 가상화와 연계해 VM과의 관계를 정립
- ISP를 두 역할로 구분
  - 인프라 제공자(InP): 물리 네트워크 자원 관리
  - 서비스 제공자(SP): InP에게 자원을 빌려 가상 네트워크를 만들고 사용자에게 서비스
- 종류
  - 링크 가상화: 단일 인터페이스를 가상화해 다수 VLAN 형성, 가상 인터페이스를 링크 스위치로 동적 구축·해제
  - 노드 가상화: 기본 노드의 CPU·메모리 등을 여러 조각으로 나눠 가상 노드로 할당, 실제 네트워크와 같은 효력의 가상 네트워크 구성
- 구조: 물리 노드·물리 링크 위에 가상 노드·가상 링크가 올라가고, 부모-자식 가상 네트워크가 재귀적으로 구성됨

## 소프트웨어 가상화
- 응용 프로그램을 가상화해, 가상 공간에서는 응용이 호스트 운영체제 위에 설치된 것처럼 동작
- 응용을 설치하는 가상 계층이나 가상 하드 드라이브를 만드는 과정이 필요
- 응용이 끝나면 동작 중 생긴 호스트 OS 변화가 모두 취소됨
- 라이브러리·레지스트리 변화 없이 수행할 수 있고, 같은 프로그램의 여러 버전을 동시에 수행 가능
- 여러 가상 계층으로 한 OS에서 충돌 없이 동시 수행, 독립 환경에서 새 응용 테스트에 유용

## 하이퍼바이저 스케줄링
| 기법 | 방식 | 특징 |
|---|---|---|
| BVT(Borrowed Virtual Time) | 가중 공평 분할, 실효 가상 시간(EVT)이 최소인 스레드에 할당 | 가상 시간을 효과적으로 빌려 씀, 장기 CPU 분할에 지장 없음 |
| SEDF(Simple Earliest Deadline First) | EDF 알고리즘 기반 실시간 스케줄링 | 마감 시한 우선 |
| 크레딧(Credit) | 비례 공평 분할 | VCPU의 자동 부하 분산 |

- 빅데이터·맵리듀스 처리 최적화용 기법
  - 동적 Dom0 가중치: Dom0은 게스트 도메인 생성과 디스크·네트워크 I/O를 관리
  - 맵리듀스 그룹 스케줄러(MRG): 그룹별·그룹 안 VM별로 스케줄링해 맵리듀스 처리 특성을 반영
  - 적응적 디스크 페어 스케줄러: 자원 경쟁으로 인한 VM 간섭을 반영

## 클라우드 컴퓨팅
- 인터넷을 이용해 서비스로 전달되는 응용과, 그 서비스를 제공하는 데이터센터의 하드웨어·시스템 소프트웨어
- 서비스 제공자와 사용자 간 협상에 따른 SLA 기반으로 동적으로 제공되는, 상호 연결·가상화된 컴퓨터로 된 병렬 분산 시스템
- 특징
  1. 요구에 따라 컴퓨팅 자원을 무한대로 사용: 프로비저닝으로 한정된 자원을 쓰던 방식에서 벗어남
  2. 자원 사용의 탄력성: 원하는 만큼 늘리고 줄일 수 있어 작게 시작해 확장 가능
  3. 사용한 만큼 지불

| 분류 | 제공 내용 |
|---|---|
| IaaS | 서버·스토리지·네트워크 등 인프라를 가상화해 인터넷으로 제공 |
| PaaS | 응용의 구축·테스트·설치까지 가능한 통합 개발 환경을 웹으로 제공 |
| SaaS | 특정 소프트웨어를 인터넷으로 제공 |

### 클라우드 에코시스템
| 주체 | 역할 |
|---|---|
| CSC(클라우드 서비스 사용자) | 여러 CSP에 서비스를 요청하고 비용을 지불하며 자원 사용 |
| CSB(클라우드 서비스 브로커) | CSC와 CSP 사이 인터페이스. 요구를 인식해 필요한 가용 자원을 자원 제공자 쪽에서 찾고, 여러 제공자와 계약해 상태·정보를 얻어 스케줄링 |
| CSP(클라우드 서비스 제공자) | 자기 데이터센터의 자원을 CSC에 제공, 과금·이용 정책 등 제약을 설정 |

- 클라우드 자원 관리 문제: 계산 모델, 데이터 모델, 데이터 지역화, 가상화, 모니터링과 기원
- 계층 구조: 사용자/브로커 → SLA 자원 할당자 → VM → PM, 그 옆에 가격 책정·회계·모니터·디스패처

### VM 배치 알고리즘
| 알고리즘 | 배치 규칙 |
|---|---|
| 최초 적합(First Fit) | 배치 가능한 첫 번째 노드 |
| 최소 용량 적합(Least-Full First) | 자원 사용률이 가장 낮은 노드 |
| 최대 용량 적합(Most-Full First) | 자원 사용률이 가장 높은 노드 |
| 다음 최초 적합(Next Fit) | 이전 작업이 배치된 노드 이후의 첫 번째 노드 |
| 임의 배치(Random) | 임의의 노드 |
| 노드 분류·패킹(Tag & Pack) | VM 종류에 맞게 분류한 노드 중 첫 번째 |

- VM 배치는 상자 채우기 문제(Bin Packing Problem)로 치환할 수 있다

### 클라우드 서비스가 추가로 요구하는 사항
1. 다중·이종 환경의 상호 운용성 — 자원 가상화, 공통 관리 기능, 자원 발견·요청, 표준 프로토콜·스키마
2. QoS 및 SLA 보장 — SLA 체결, 서비스 수준 달성(감시·조치), 서비스 마이그레이션
3. 보안 — 인증·권한, 다중 보안 구조, 차단(VM 간 간섭 방지), 위임, 보안 정책 변화
4. 자원 관리 비용 최소화 — 데이터 접근·일관성·안정성·통합·위치 관리
5. 데이터 관리 — 락인, 비밀성, 감사성, 전달까지 포함
6. 확장성
7. 가용성 — 재난 관리, 고장 관리

### 데이터 지역성·SLA 기반 관리
- 노드 이종성을 고려한 작업 분배, 작업 복사와 가속용 추가 노드 활용, 이종성으로 인한 네트워크 비용 해결
- 데이터 지역성을 고려해 스케줄링하면 작업 큐 지연을 줄이고, 노드 간 분산 작업 배치로 네트워크 오버헤드를 줄임
- 이종 노드에 맞춰 저장 데이터 양을 적절히 분배하고, 블록을 무작위로 배치하면 부하 분산에 효과적
- SLA 기반 관리: 측정 모듈 → 예측 모듈 → 배치 모듈이 VM 마이그레이션 명령을 내려 SLA를 보장

### CSB의 자원 공급 4형태
| 형태 | 내용 | 특징 |
|---|---|---|
| 1VM4ALL | 하나의 VM에 작업을 모두 할당 | 비용 최소, 즉각 할당 어려움 |
| 1VMPerJob | 하나의 VM에 하나의 작업 | 즉각 할당, 작업 시간이 단위 사용 시간(BTU)보다 짧으면 낭비 |
| Bin-Packing | First Fit·Best Fit·Worst Fit 휴리스틱으로 할당, 필요할 때만 VM 임대 | 1VM4ALL보다 빠르고 1VMPerJob보다 낭비가 적음 |
| Relax | 종료 시간에 여유가 있을 때 유휴 자원을 기다렸다가 유연하게 할당 | 자원 낭비 최소 |

- First Fit은 할당 가능한 첫 VM, Best Fit은 잔여 사용 시간이 작업 처리 시간과 가장 가까운 VM에 할당하는 방식

## 정리
- 가상화는 서버·데스크톱·스토리지·네트워크·소프트웨어로 대상이 나뉘고, 서버 가상화는 "하이퍼바이저의 위치"와 "게스트 수정 여부"로 다시 나뉜다
- 클라우드는 이 가상화 위에 SLA·과금·브로커 개념을 얹은 것으로, 자원 관리의 목표는 결국 VM 배치와 마이그레이션 최적화다
