## 우지(Oozie)
- 워크플로우 실행 중 특정 단계에서 결정을 내릴 수 있도록 XML 파일로 설정
- Java 서블릿 컨테이너에서 실행되는 Java 웹 응용으로, 사용자가 기능을 확장할 수 있는 API도 지원
- 아즈카반에 비해 인터페이스가 강력하지만 복잡해, 필요한 기능에 따라 작업을 선택해야 함
- 아즈카반과 함께 하둡 기반 워크플로우 제어 시스템

### 노드 종류
| 구분 | 노드 | 역할 |
|---|---|---|
| 제어 플로우 | start, end, fail | 워크플로우의 시작과 끝 정의 |
| 제어 플로우 | decision, fork, join | 실행 경로 제어 |
| 동작 | map-reduce, 커맨드 등 | 실제 계산·처리 작업을 원격 시스템에서 시작 |

- 예: start → wordcount(맵리듀스) → end, 오류 시 kill로 빠지는 흐름

## 그린플럼(Greenplum)
- Shared-Nothing MPP(Massively Parallel Processor) 구조의 데이터베이스로 PostgreSQL 기반
- 저장 데이터는 연산에 따라 행 기반 또는 열 기반을 선택
- 데이터는 서버에 세그먼트 단위로 저장되고, 로그 적재(Log Shipping) 방식으로 세그먼트 단위 복제해 가용성 확보
- Java와 R로 쓴 사용자 함수를 지원하고, 빠른 프로세서와 큰 메모리의 클러스터에서 돌도록 분산 구조 지원
- 표준 SQL 인터페이스를 쓰고, RAID 기술로 여러 시스템에 데이터를 복제해 손실을 최소화
- 구성: 마스터 서버(질의 계획·디스패치) - 네트워크 - 세그먼트 서버(질의 처리·데이터 저장), 외부 데이터 소스 로딩·스트리밍
- EMC Greenplum UAP(Unified Analytics Platform)는 관계형 DB와 맵리듀스를 하나로 합친 통합 분석 소프트웨어
  - 정형 데이터는 Greenplum DB(MPP), 비정형은 Greenplum HD로 나눠 처리
  - 데이터를 공유하지 않아 DB 간 병목이 없고, 필요한 부분만 읽는 열 기반 DB가 핵심 기능

## EC2(Elastic Compute Cloud)
- 개발자가 웹 스케일 컴퓨팅을 쉽게 쓰도록 설계한 아마존의 웹 서비스
- 웹 서비스 인터페이스로 다양한 운영체제 인스턴스를 시작
- 메모리와 CPU 자원을 시간 단위로 지정해 컴퓨터를 임대
- 슈퍼유저 권한으로 리눅스·윈도 서버 네트워크에 접근할 수 있어 소프트웨어 설치와 시스템 설정이 자유로움
- 엘라스틱 블록 스토리지(EBS)와 S3를 기존 파일 시스템과 함께 활용
- 엘라스틱 맵리듀스로 하둡 클러스터를 간단히 구성
- 장점: 병목이 생기면 가상 머신을 자동으로 늘려 성능이 낮은 시스템으로도 해결
- 단점: 가상화 계층이 실제 하드웨어 구성 설정을 제한

## 히로쿠(Heroku)
- 서버 관리를 신경 쓰지 않고 응용 개발·관리에만 집중하게 해 주는 클라우드 개발 도구
- Heroku client gem으로 명령어 모드에서 응용을 생성·관리
- Git으로 개발한 응용을 생성·배포
- 실행 중인 응용은 원격 Ruby 콘솔과 Rake 명령으로 제어
- 여러 언어를 지원하지만 Ruby/Rails 기반 웹 응용에 특히 빠르게 적용

## R 프로그래밍 언어
- 통계 소프트웨어를 개발하고 데이터를 분석하는 데 널리 쓰임
- 패키지 개발이 쉬워 프로그래밍 비전공자인 통계학자 사이에서 많이 활용
- 핵심 패키지와 함께 설치되고, CRAN에서 다양한 패키지를 내려받음
- 분석 결과를 시각화할 수 있고, 수학 기호가 정확히 표시되는 출판물 수준의 고화질 그래프를 제공
- 행렬 계산 도구로도 활용

## 파이프(Pipes)
- 컴포넌트를 드래그 앤 드롭하는 그래픽 인터페이스 사용
- 출처의 정보를 끌어와 어떤 규칙으로 가공할지 결정
- 방대한 데이터 처리에는 어렵지만, 무료 전문가용 응용으로 여러 소규모 프로세스를 연결할 수 있음
- 야후가 제공하는 데이터 파이프라인 생성 웹 응용

## 미케니컬터크(Mturk, Mechanical Turk)
- 아마존이 HIT(Human Intelligence Task)를 제공하려고 사람과 컴퓨터의 수많은 협동 작업을 온라인으로 관리
- 사람들의 남는 노동력을 저렴하게 활용하는 것이 목표
- 비즈니스 목표 달성에 도움을 줄 작업자 가상 커뮤니티에 접근 가능
- 컴퓨터가 못 하는 일에 사람의 인지 능력을 쓰게 해 주는 크라우드소싱 인터넷 마켓플레이스
- 강력한 API와 명령 도구로 인간 지능이 필요한 작업을 다수 인력에 프로그래밍 방식으로 배포
- HIT에 결과·형식·표시 방식·지급 금액을 정의하고 마켓플레이스에 올린 뒤, 조건을 만족하는 결과가 올라왔는지 조회

## 솔라/루씬(Solr/Lucene)
- 아파치 루씬 기반의 기업 검색 플랫폼인 솔라는 Java로 작성
- 톰캣 같은 서블릿 안에서 독립적인 전체 텍스트 검색 서버로 동작
- 강력한 전체 텍스트 검색, 다각적 검색, 동적 클러스터링, 풍부한 문서 핸들링을 지원
- 파일을 인덱싱하는 검색 엔진을 넘어, XML 요청을 HTTP로 보내는 웹 서비스 API가 있는 검색 서버
- 검색 서버 URL로 인터넷에서 파일 질의·인덱싱 응용을 만들 수 있고, 다른 솔라 서버로 캐싱·복사가 가능

## 엘라스틱서치(ElasticSearch)
- 아파치 루씬 기반의 분산형 오픈소스 검색 엔진 서비스
- 장점: 문서 지향, 긴 신뢰성, 비동기 쓰기, 실시간 검색, 쉬운 설치·사용, 짧은 지연의 검색·인덱스 갱신
- Java로 개발, 한 클러스터에 문제가 생기면 진행 중인 작업이 복제된 다른 클러스터로 자동 이동
- 다중 타입을 갖는 다중 테넌트 특징, 단일 고장점(SPOF) 제거
- 하나 이상의 인덱스, 인덱스마다 하나 이상의 타입, 인덱스 계층별 제어 가능
- JSON 파서로 인덱스 데이터를 다루기 쉬움

## 데이터미어(Datameer)
- 종류가 다른 방대한 데이터를 모아 읽어 들여 하둡 프레임워크에 저장하고, 분석 도구를 제공하는 플랫폼
- 하둡의 복잡성을 숨긴 채 분석 도구를 제공
- 10TB 이상의 데이터 소스를 대상으로 함
- 방대한 데이터를 처리하는 하둡 기반 비즈니스 인텔리전스 마켓을 목표로, 단순한 프로그래밍 환경을 제공
- 분석 타입을 명세하면 맵리듀스 작업으로 변환하고, 데이터 타입 변환 도구와 시각화 기능 제공

## 인포스피어 빅인사이트(InfoSphere BigInsights)
- 하둡 기반에 IBM 연구팀의 분석 기술과 관리·워크플로우·프로비저닝·보안 기능을 접목한 다목적 솔루션
- 인터넷의 정형·비정형 데이터를 관리·분석
- 대표 컴포넌트: 스프레드시트 기반 분석 모듈 BigSheets
- 인포스피어 스트림즈(InfoSphere Streams)는 정형·비정형을 모두 지원하는 확장성 높은 스트리밍 분석 솔루션으로, 짧은 시간에 방대한 스트리밍 데이터를 지속 분석

## 도구 비교
| 도구 | 성격 | 핵심 | 고려할 점 |
|---|---|---|---|
| 우지 | 워크플로우 제어 | XML 정의, 분기·병렬 노드 | 강력하지만 복잡 |
| 그린플럼 | MPP 데이터베이스 | 세그먼트 분산, 열 기반 | 정형 데이터 분석에 강함 |
| EC2 | IaaS | 시간 단위 임대 | 가상화 계층 제약 |
| 히로쿠 | PaaS | git 배포, 서버 관리 불필요 | Ruby/Rails에 최적 |
| R | 분석 언어 | 통계·시각화, CRAN | 프로그래밍 일반 용도 아님 |
| 파이프 | GUI 파이프라인 | 드래그 앤 드롭 | 대용량에는 부적합 |
| Mturk | 크라우드소싱 | 사람 인지 작업 분배 | 품질 관리 필요 |
| 솔라/루씬 | 검색 서버 | 전체 텍스트 검색 | 인덱스 운영 필요 |
| 엘라스틱서치 | 분산 검색 | 실시간 검색, 복제 | 클러스터 설계 |
| 데이터미어 | 분석 플랫폼 | 맵리듀스 자동 변환 | 하둡 의존 |

## 정리
- 이 차시 도구는 네 갈래로 나뉜다: 워크플로우(우지), 분석 DB·클라우드(그린플럼, EC2, 히로쿠), 분석 언어·도구(R, 파이프, Mturk), 검색·분석 플랫폼(솔라, 엘라스틱서치, 데이터미어, 빅인사이트)
- 앞 차시의 처리 기술이 "계산"이라면, 여기서는 "언제 어떤 순서로 돌릴지"와 "결과를 어떻게 찾고 보여 줄지"를 다룬다
