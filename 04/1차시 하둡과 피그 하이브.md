## 처리 기술의 관점 변화
- 기존 처리 방식: 방대한 데이터를 **한 번에 얼마나 빠르게** 처리하는지에 초점
- 현재 처리 기술: 저장된 데이터를 사용자가 **원하는 부분에, 원하는 시간에** 처리하는 데 초점
- 저장이 끝난 데이터를 어떤 도구로 다룰지가 이번 주차의 주제

## 하둡(Hadoop)
- 엔진 형태의 미들웨어와 소프트웨어 개발 프레임워크로 구성
- 즉시 응답해야 하는 트랜잭션 처리보다, 데이터를 모은 뒤 처리해 작업이 끝나면 응답하는 방식으로 설계
- 여러 컴퓨터로 구성된 클러스터로 방대한 데이터를 처리하는 분산 처리 프레임워크
- 어느 정도 시간이 걸리는 대량 처리에 적합

### 맵리듀스의 구성
| 단계 | 역할 |
|---|---|
| 맵(Map) | 하나의 큰 데이터를 여러 조각으로 나누어 처리 |
| 리듀스(Reduce) | 처리된 결과를 하나로 모아 취합하고 결과를 도출 |

### 실행 단계
1. 입력 HDFS의 조각 0~2를 각각 맵이 처리
2. 맵 결과를 정렬·복사하고 병합
3. 리듀스가 파트 0·1을 만들어 출력 HDFS에 저장
4. 중간·출력 결과는 HDFS 복제로 보호

- 정리하면 입력 분할 → 맵 → 정렬·병합(셔플) → 리듀스 → 출력의 흐름이고, 병렬성은 조각 수와 리듀스 수로 결정된다

## 피그(Pig)
- 고수준 언어로 데이터 분석을 프로그래밍할 수 있는 대량 데이터 분석 플랫폼이며, 이를 평가할 인프라도 함께 제공
- 대규모 병렬 처리에 대응하는 구조라 대규모 데이터 처리에 유리
- 아파치 하둡 세부 프로젝트 중 하나로, **절차적** 데이터 처리 언어 프레임워크

### 피그 라틴(Pig Latin)
- 데이터 흐름을 명시적으로 보여 주는 코드를 작성할 수 있고, 이해하기 쉽고 유지보수가 용이
- 시스템이 실행을 자동 최적화하므로 사용자는 효율성 대신 프로그래밍 내용에 집중
- int, long, double 같은 기본형 외에 릴레이션(Relation), 백(Bag), 튜플(Tuple) 같은 고수준 구조 제공
- Filter, Foreach, Group, Join, Load, Store 등 관계 연산을 지원하고 사용자 정의 함수도 쉽게 정의
- 작성한 프로그램은 논리적 실행 계획으로, 다시 맵리듀스 실행 계획으로 변환됨

```text
A = Load 'file1' AS (x, y, z);
B = Load 'file2' AS (t, u, v);
C = Filter A By y > 0;
D = Join C BY x, B By u;
E = Group D BY z;
F = Foreach E Generate group, Count(D);
Store F Into 'output';
```

- 위 코드는 Load → Filter → Join → Group → Foreach → Store의 논리 계획으로 바뀌고, 이것이 맵리듀스 작업으로 내려간다
- SQL처럼 "무엇을 원하는지"만 쓰는 것이 아니라 "어떤 순서로 데이터를 흘릴지"를 쓰는 점이 하이브와의 차이

## 하이브(Hive)
- SQL처럼 **선언적**으로 데이터를 처리
- HDFS나 HBase 같은 빅데이터 원본을 HiveQL 질의 언어로 분석
- 구성: 맵리듀스 기반 실행 부분 + 데이터가 저장된 공간의 메타데이터 정보 + 사용자·응용이 입력한 질의를 받아 실행하는 부분
- 스칼라 값, 집합, 테이블 수준에서 사용자 정의 함수를 지정할 수 있어 확장 지원
- 하둡에서 동작하는 SQL 프로그램을 구현할 수 있는, 하둡 기반 데이터 웨어하우스 인프라
- 관계형 데이터베이스에 익숙한 개발자에게 좋은 인터페이스를 제공

구성도
- 클라이언트: 커맨드라인 인터페이스, 웹 인터페이스, JDBC/ODBC 드라이버, Thrift 서버
- 내부: 컴파일러, 옵티마이저, 실행기(Executor)와 메타스토어
- 하둡: 잡트래커 + NameNode/DataNode(맵리듀스 + HDFS)

## 캐스캐이딩(Cascading)
- JVM 기반 언어로 하둡 클러스터의 데이터 처리 워크플로우를 만들고 실행하도록 지원
- 하둡용 오픈소스 소프트웨어 추상화 계층으로, 피그·하이브처럼 맵리듀스 작업의 복잡성을 숨겨 줌
- 제공 API
  - 데이터 처리 API: 복잡한 데이터 흐름 정의, 데이터 중심 프레임워크 개발
  - 데이터 통합 API: 통합 문제를 풀기 전에 기능을 추가하고 실제 환경과 비슷하게 테스트
  - 프로세스 스케줄러 API: 다른 응용과 호환해 프로세스 단위 스케줄 지정·예약
- 기업의 Java 개발 환경에 맞춘 설계로 대규모 개발·테스트가 가능
- Java 기반이면서 스칼라, 클로저, 루비, 자이썬, 그루비 등 JVM 언어를 지원
- 내결함성: 일부 서버가 실패하면 다른 서버로 작업을 넘겨 손실을 최소화
- 활용: 광고 타깃팅, 로그 파일 분석, 생물정보학, 기계학습, 예측 분석, 웹 콘텐츠 마이닝, ETL 응용

## 캐스칼로그(Cascalog)
- Clojure로 개발되어 함수형 데이터 처리 인터페이스를 제공
- 데이터로그(Datalog) 언어의 영향을 받았고, Cascading을 바탕으로 개발되어 피그·하이브·캐스캐이딩을 대체할 수 있는 도구
- SQL보다 훨씬 높은 수준의 사용자 추상화를 제공하고, 작성한 코드는 하둡에서 처리되도록 연동
- 하둡 클러스터에서 **작은 규모**의 데이터를 처리하는 코드에 적합
- 기능·필터·집계가 모두 같은 구문을 사용해 작성이 간편하고, 널 값 처리 기법을 도입해 오류를 줄임

## 미스터잡(Mrjob)
- 하둡 이후 파이썬으로 하둡을 쉽게 프로그래밍하게 해 주는 프레임워크
- 미국 맛집 추천 사이트 옐프(Yelp)가 만든 파이썬 라이브러리
- 처리 코드를 작성한 뒤 한 곳에서 도는 엘라스틱 맵리듀스나 하둡 클러스터에서 실행
- 추상화나 내장 연산은 지원하지 않지만, 각 단계에 디버거를 붙여 실제 코드 동작을 파악할 수 있음
- 같은 계열: Hadoopy, Dumbo

## S4(Simple Scalable Streaming System)
- 실시간 개인화 검색 광고의 선택·위치 지정, 야후 검색 서비스에 필요한 데이터 마이닝·기계학습을 지원
- 임의의 이벤트 스트림 처리에도 응용할 수 있는 오픈소스
- ZooKeeper를 사용해 클러스터의 분산 실행을 관리
- 구성: 프로세싱 노드(통신 계층 + 프로세싱 요소 컨테이너), 이벤트를 받는 Listener, 라우팅·로드밸런싱·장애 극복 관리, Dispatcher/Emitter
- 처리 요소(PE)를 여러 개 두고 이벤트를 흘려보내는 스트림 처리 모델

## 맵알(MapR)
- 하둡 배포판 공급업체 맵알 테크놀로지스가 높은 신뢰성을 요구하는 기업에 제공하는 상업용 하둡
- HDFS를 대체하는 자체 파일 시스템을 쓰고, 분산된 네임노드로 신뢰성을 높임
- 파일 시스템 성능이 개선되고 백업이 쉬움
- NFS와 호환되어 데이터 전송이 단순해지고, 맵리듀스 처리량과 입출력 속도가 개선
- 프로그래밍 모델은 하둡과 같지만 주변 인프라를 개선한 기업용 통합 솔루션
- 장점: 쉬운 관리, 신뢰성 향상, 빠른 속도
- 스토리지 서비스: Direct Access NFS, 실시간 스트리밍 볼륨, 미러, 스냅샷, 데이터 배치, 네임노드 없는 구조, Direct Shuffle, 상태 기반 장애 복구·자가 치유

## 아큐누(Acunu)
- 기존 파일 시스템을 대체해 새로운 저수준 저장 계층을 제공하며, 하둡보다는 Cassandra를 대체하려고 개발
- 분석 질의·범위 질의에 효과적인 Stratified B-Tree를 구현한 저장 플랫폼
- 오픈소스로 공개한 Castle은 커널 레벨에서 키-값을 저장해 속도를 높임
- 관계형 DB와 비슷한 자동 구성과 관리 기능 제공
- Cassandra와 하둡의 표준 API를 유지해 호환성을 높이고, Cassandra의 한계를 개선하려 함
- 소규모·저렴한 하드웨어로 더 많은 작업을 하는 것이 목표이며, 제어·모니터링 관리 도구를 제공

## 아즈카반(Azkaban)
- LinkedIn의 오픈소스 프로젝트
- 각 서비스가 여러 연산을 묶어 비즈니스 로직으로 실행하도록, 사용자가 원하는 워크플로우를 정의하는 배치 스케줄러
- 세부 작업까지 관리하기 어려운 문제를 해결하려고 작업을 관련 있는 여러 단계로 나눠 처리
- 오류가 나면 로그로 찾아 관리자에게 메일로 알리고, 웹 인터페이스로 진행 상황을 파악
- 유닉스 명령어나 Java 프로그램을 부르는 최소한의 명령어로 된 텍스트 파일로 처리할 일을 구성
- 복잡한 내부 구현은 각 명령어·Java 프로그램이 담당

## 처리 도구 비교
| 도구 | 언어·방식 | 성격 | 적합한 경우 |
|---|---|---|---|
| 피그 | 피그 라틴(절차적) | 데이터 흐름 기술 | 대규모 배치, 흐름이 분명한 작업 |
| 하이브 | HiveQL(선언적) | 데이터 웨어하우스 | SQL에 익숙한 사용자, 집계·조회 |
| 캐스캐이딩 | JVM 언어 API | 추상화 계층 | Java 기반 기업 개발, ETL |
| 캐스칼로그 | Clojure(Datalog) | 함수형 추상화 | 작은 규모 데이터, 복잡한 질의 표현 |
| 미스터잡 | 파이썬 | 맵리듀스 래퍼 | 파이썬 개발, 단계별 디버깅 |
| S4 | 스트림 처리 | 실시간 이벤트 | 개인화 광고, 검색 |
| 아즈카반 | 텍스트 파일 정의 | 배치 스케줄러 | 여러 작업의 순서 관리 |

## 정리
- 맵리듀스의 "나누고 모은다"를 감추는 방향으로 추상화가 발전: 캐스캐이딩 → 피그 → 하이브
- 실행 관리(아즈카반)와 스트림 처리(S4)는 처리 자체보다 운영·실시간 요구를 담당
