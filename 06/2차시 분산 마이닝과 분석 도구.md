## 분산 처리를 이용한 마이닝 처리 단계
- 빅데이터 마이닝은 단일 머신에서 감당하기 어려우므로 계층을 나눠 처리
| 계층 | 사용 기술 |
|---|---|
| 마이닝 처리 | 모으기, 후처리, 전처리, 분석 |
| 데이터 액세스 API | Bigtable, HBase |
| 고수준 API | 소잴(Sawzall), Pig, 드라이애드(Dryad) |
| 분산 파일 시스템 | GFS, HDFS, KFS |
| 실행 프레임워크 | 맵리듀스 |

- 아래 세 계층은 앞 차시(하둡·HBase)에서 다룬 저장·처리 기술이 그대로 받쳐 주는 구조

## 연관규칙: Apriori의 맵리듀스화
- Apriori는 데이터마이닝 분야의 대표적인 연관규칙 알고리즘
- 맵리듀스는 각 트랜잭션의 모든 부분집합을 만든 뒤 각 부분집합의 개수를 세는 방식으로 문제를 해결
- 흐름: 데이터 분할(Split 0~4) → 맵1~3이 후보 집합에 속한 아이템 개수 계산 → 리듀스가 j-길이 빈번 아이템 집합 도출
- 분산 컴퓨팅 기술인 knowledge 그리드 기반의 **Apriori Grid Service** 제안
  - 모바일 클라이언트, 서비스 제공자, Expert System, 지식 기반 레포지토리(KBR), 홈·방문자 위치 레지스터(HLR·VLR), 데이터 제공자 A·B를 연계
  - 사용자의 이동 예상 경로를 예측하는 알고리즘에 병렬 Apriori를 적용

## 분류: MReC4.5
- Pitchaimalai의 연구는 DBMS와 하둡 분산 파일 시스템에서 나이브 베이즈 분류의 효율성을 평가
- 기존 결정 트리 분류 알고리즘 C4.5를 맵리듀스 기반의 MReC4.5로 개선
- 데이터를 분산해 **맵에서 분류기를 만들고, 리듀스에서 합치는** 방식
- 구성: 분할 단계(마스터가 D를 Partitions로) → 맵-분류 단계(작업 1~m이 D1~Dm으로 C1~Cm 생성) → 리듀스-합치기 단계(C1~Cm → C)

### 소요 시간 실험 지표
| 약어 | 의미 |
|---|---|
| NN | 계산 노드 수 |
| BN | 기본 분류기 수 |
| PT | MReC4.5의 분할 시간 |
| MT | 맵 함수 수행 시간 |
| RT | 리듀스 함수 수행 시간 |
| TT | MReC4.5 실행의 총 소요 시간 |

- 실험 결과는 노드 수·기본 분류기 수·분할 수를 바꿔 가며 맵·리듀스·총 시간을 비교하는 표로 제시됨(예: 노드 3, 기본 분류기 3, 분할 3일 때 45초·5분 48초·3분 21초·9분 54초)

## 군집화: K-means의 맵리듀스화
- 맵: 입력된 점에서 가장 가까운 점(중심)을 찾아 키-값으로 출력
  - `<center1, p11>`, `<center1, p12>`, `<center2, p21>`, `<center3, p31>` …
- 리듀스: 중심별로 모인 점들로 새 중심을 계산
  - `<center1, [p11, p12]>` → `<center1, center1'>`
- 모든 군집의 내용이 더 이상 바뀌지 않을 때까지 반복

### 서브스페이스 군집화
- 서브스페이스 군집화를 맵리듀스 프레임워크로 구현해 여러 머신에 데이터를 분산하고, 각 머신이 주어진 데이터만 계산하도록 군집화
- 기본 알고리즘은 Apriori 방식을 이용해 낮은 차원에서 밀집 영역을 찾아 나감

## 빅데이터 주요 분석 기술
| 기술 | 최초 개발 | 최초 공개 | 주요 기능 |
|---|---|---|---|
| NLTK | E. Loper | 2001 | 글의 문장 분할, 단어 분할 |
| OpenNLP | 아파치 | 2010 | 비정형 텍스트에서 의미 있는 용어 추출 |
| Boilerpipe | C. Kohlschutter | 2010 | 웹 페이지의 불필요 데이터 제거, 필요 정보 추출 |
| WEKA | I. Witten | 1993 | 데이터마이닝·기계학습 알고리즘을 포함한 분석 프로그램 |
| Mahout | 아파치 | 2009 | 확장 가능한 기계학습 알고리즘 개발 프로젝트 |
| scikit-learn | D. Cournapeau | 2011 | 오픈소스 기계학습 라이브러리 |

### NLTK(Natural Language ToolKit)
- 특정 문제를 해결하려고 알고리즘 생성 과정에 필요한 빌딩 블록 제공
- PHP, Python 등으로 제공되는 툴킷이 있으며 연구자들이 많이 쓰는 프레임워크
- 일반적인 접미사를 제거해 중심 단어를 추출하거나, 전체 텍스트에서 동의어를 찾으려고 기계가 분석 가능한 사전 형태로 데이터를 정형화

### OpenNLP
- 비정형 텍스트에서 사람·기관 이름, 특정 장소, 시간 등을 추출하는 모델을 포함한 라이브러리
- Java 기반 자연어 처리 솔루션
- 응용 프로그램에 적합한 형태로 자연어 처리 코드를 스스로 생성
- 비정형 텍스트를 문장·단어로 분리한 뒤 다양하게 클래스화하는 표준 컴포넌트를 포함

### Boilerpipe
- 웹 페이지에서 불필요한 부분을 제거해 실제로 필요한 정보만 추출하는 프레임워크
- HTML에서 가장 중요한 콘텐츠를 찾는 알고리즘을 적용한 Java 기반 라이브러리
- 모든 종류의 웹 콘텐츠에서 거의 완벽한 전처리 도구를 만들 수 있음
- 뉴스·기고 페이지 분석에 많이 쓰고, 최근에는 블로그·SNS에서도 유용하게 사용

### WEKA
- 무료로 배포되는 Java 기반 오픈소스 데이터 분석 프로그램
- 데이터마이닝 알고리즘을 사용자가 개인화할 수 있고, 플러그인 형식이라 고유 알고리즘을 쉽게 접목
- 사용이 간편한 명령과 이해하기 쉬운 인터페이스 제공

### Mahout
- 확장 가능한 기계학습 알고리즘을 만드는 것이 주목적, 아파치 라이선스로 무료 사용
- 방대한 데이터 집합에서 기계학습 알고리즘을 실행하는 오픈소스 프레임워크
- 확장성·처리량을 보장하려고 하둡 기반 병렬 형식으로 구성
- 공통 작업이 많은 알고리즘에 적합하며, 군집화·분류·추천 시스템 분석 환경에 알맞음
- 구성: 랩톱 → Mahout → 하둡 맵리듀스 → HDFS 클러스터 (협력 필터링·클러스터링·분류)

### scikit-learn
- 서포트 벡터 머신, 로지스틱 회귀, 군집화 등 여러 분석 기법 제공
- 이를 편리하게 쓰도록 고수준 인터페이스 제공
- 복잡한 문제를 해결하는 알고리즘이나 해결 과정에 초점을 맞추어, 과정에 치중하는 사용 환경에 더 적합

## 정리
- 분산 마이닝의 공통 패턴은 "부분 결과를 만들고(맵), 합친다(리듀스)"이며, Apriori·C4.5·K-means 모두 이 틀로 옮길 수 있다
- 도구 선택 기준은 세 가지다: 데이터 규모(단일 vs 하둡), 언어 생태계(Python vs Java), 목적(전처리·분류·추천)
