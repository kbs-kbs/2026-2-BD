## 빅데이터의 등장 배경
- 1990 이후 인터넷이 확산되면서 데이터가 무수히 발생
- Fat 클라이언트 (2-Tier C/S) -> Fat 서버 (3-Tier C/S)
- 앱 까보면 DB 비번 털리는데 이게 말이 돼? - 웹 애플리케이션 서버(WAS)'만 DB 비밀번호를 알게.
- 폐쇄망 중심이었기 때문에 웹으로 가기위한 기술적 필연이었음
- 데이터양 증가로 기존의 저장, 관리, 분석 기법으로는 처리에 한계 발생
- 패러다임의 변화:
  - PC 시대(아날로그와 대비되는 디지털이라는 키워드) - 인터넷 시대(오프라인-온라인) - 모바일 시대(유선-무선) - 스마트 시대(도구-비서)

### 데이터 규모
- 1990 100엑사바이트
- 2011 제타바이트 진입
- 2020 제타바이트 본격화

### 데이터 유형
- 정형 데이터
- 비정형 데이터
- 사물정보, 인지정보

### 데이터 특성
- 구조화
- 다양성, 복합성
- 현실성, 실시간성

### 빅테이터가 차세대 이슈로 떠오르는 이유
- 정보화 시대 - 스마트 시대 정보통신기술의 주도권이 데이터로 이동
- 관계형- 비관계형
- 시맨틱 분석으로 나아감



## 빅데이터의 개념과 속성

규모, 다양성, 속도(3V) + 정확성(4V) + 가치(인프라 구조 시스템을 구현하는 비용, 5V)

### 광의의 빅테이터 정의
- 인재/조직
- 데이터 처리/축적/분석 기술
- 데이터(비정형, 정형)

### 규모와 다양성에 따른 빅데이터의 위치
- 규모가 큼 다양성(비정형-정형) 큼

### 종류
- 정형: 고정된 필드 있음
- 반정형: 고정된 필드는 없음. xml이나 json은 내장 태그는 정형이지만 사용자 정의 태그(비정형)를 지원하기 때문에 반정형이라고 할 수 있고 html은 정해진 내장 태그만 쓰지만 배치와 구조가 유연하기 때문에 반정형.
- ... 이게 거의 99% 교수나 강사가 말하는 분류
- 사실 파일 하나 보고 정형/반정형을 나누는 것은 불가능. 엑셀 그림은 뭔데?
- 데이터 전송자와 수신자 사이의 약속(관계)가 핵심.
- 포맷이 JSON·HTML이라도 양측이 엄격한 규칙을 맺고 표 형태로만 주고받는다면 실질적인 '정형 데이터'이다
- 언제든 항목이 바뀔 수 있도록 유연한 예외를 열어둔 관계일 때 비로소 '반정형 데이터'가 된다.
- 이걸 깨달으면 현실에 존재하는 모든 데이터는 컴퓨터가 읽는 순간 최소한의 형식(디지털 규격)을 가질 수밖에 없으므로, 반정형이라는 모호한 중간 개념은 무의미해짐
- 그래서 나는 반정형이라는 개념은 없어져야 한다고 본다.
- 아무런 사전 약속 없이 던지는 데이터만 비정형이라고 할 수 있다. 그러니까 전송자와 수신자 관계의 유무로 판단하자는 것이다. 그러니까 마치 자연을 찍는 사진 작가처럼. 자연은 사진 작가를 고려하지 않는다.
